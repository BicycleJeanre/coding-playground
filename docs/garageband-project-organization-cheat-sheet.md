# GarageBand Project Organization Cheat Sheet

**Last Updated: 2026-05-01**

This cheat sheet is about keeping GarageBand projects readable when they get bigger. It focuses on naming, color coding, sectioning, versioning, and reducing track clutter before the session becomes hard to manage.

## Core Idea

A project becomes hard to work with when you can no longer answer these questions quickly:

- What is this track for?
- Which parts are finished?
- What still needs work?
- Where does the song change sections?
- Which version is the latest one?

## Naming Rules

### Track Names

Use names that say what the track does, not just what it is.

Good examples:

- `VOX - Lead`
- `VOX - Doubles`
- `DRUM - Kick`
- `DRUM - Snare`
- `BASS - Sub`
- `BASS - Mid`
- `GTR - Rhythm L`
- `FX - Risers`
- `REF - Original`

### Region Names

Rename important regions as soon as they matter.

Good examples:

- `Intro vocal take`
- `Verse 1 comp`
- `Drop bass riff`
- `Breakdown pad`
- `Chorus hook`

## Color Coding

Use color as a fast visual map.

Suggested pattern:

- Drums: one color family
- Bass: one color family
- Vocals: one color family
- Lead instruments: one color family
- FX and transitions: one color family
- Reference or raw files: a separate neutral color

The goal is not decoration. The goal is to spot structure instantly.

## Track Grouping

Put related tracks next to each other.

Typical order:

1. Drums
2. Bass
3. Main instruments
4. Vocals
5. FX
6. References

This makes it easier to mute, solo, and compare parts without hunting.

## Versioning

Use version numbers when a change is important enough to revisit.

Examples:

```text
track-name_v01.band
track-name_v02.band
track-name_mix-v03.band
track-name_final-v04.band
```

Useful version moments:

- After a major arrangement change
- After a cleanup pass
- After a mix revision
- Before experimental edits

## Section Marking

Use the arrangement track or a similar workflow to label the song map.

Typical labels:

- Intro
- Verse
- Chorus
- Breakdown
- Build
- Drop
- Outro

For longer or spoken projects:

- Part 1
- Part 2
- Segment A
- Segment B

## Keeping Sessions Clean

### Do This

- Keep raw material in a reference track
- Mute unused takes
- Delete experiments once they are no longer useful
- Lock finished parts if the project supports it
- Keep a rough mix bounce for comparison

### Avoid This

- Leaving every test idea active
- Calling everything `Track 1`
- Keeping ten nearly identical edits on top of each other
- Mixing and arranging at the same time without a plan

## Large Project Strategy

When the session starts getting crowded, simplify before adding more.

1. Rename everything.
2. Group tracks by function.
3. Hide or mute what is not needed.
4. Commit finished sections.
5. Export stems if needed.
6. Save a new version before large changes.

## Folder Habit

Use a repeatable folder layout:

```text
Project Name/
  GarageBand/
  Audio/
  Exports/
  References/
  Notes/
```

That keeps source material, working files, and exported mixes separated.

## Organization Checklist

- Every important track has a meaningful name
- Related tracks are next to each other
- Colors are consistent
- Unused takes are muted or removed
- Major sections are labeled
- The latest version is obvious
- Exports are stored separately from the working file

## Rule Of Thumb

If you need to stop and think about where something is, the session is already too messy. Fix the organization before continuing the arrangement or mix.
